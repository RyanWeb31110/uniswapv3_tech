- 📐 **Tick Spacing**:如何通过价格间距优化不同类型代币对的交易效率

## 一、工厂合约的核心作用

### 1.1 为什么需要工厂合约?

Uniswap 采用了**池子分离架构**:每个代币对都有独立的 Pool 合约。这种设计虽然灵活,但也带来了管理上的挑战:

**问题场景**:
- 假设你想用 ETH 兑换 DAI,但是没有 ETH/DAI 的直接池子
- 你可以通过中间代币完成兑换:ETH → USDC → DAI
- 但是,如何找到这些池子的地址呢?手动查询太繁琐了!

**工厂合约的三大核心功能**:

#### 1. 集中注册表 📋

工厂合约就像一个"池子地址簿",记录了所有已部署的池子:

```solidity
// 三维映射:token0 => token1 => tickSpacing => pool地址
mapping(address => mapping(address => mapping(uint24 => address))) public pools;
```

通过代币地址和 tick spacing,就能快速查找对应的池子地址。

#### 2. 简化部署流程 🏭

EVM 支持"合约部署合约"的特性,工厂合约利用这一点,提供了标准化的池子部署流程:

```solidity
// 用户只需调用一个函数
pool = factory.createPool(tokenA, tokenB, tickSpacing);

// 而不是手动部署、初始化、注册...
```

#### 3. 可预测地址 🔮

这是工厂合约最巧妙的设计!使用 CREATE2 操作码,池子地址变成了**确定性的**:

- 相同的代币对 + tick spacing,永远产生相同的池子地址
- 无需查询注册表,就能在任何地方计算出池子地址
- 任何人都可以验证地址的正确性

## 二、CREATE 与 CREATE2:两种部署方式的区别

在深入工厂合约实现之前,我们需要理解 EVM 的两种合约部署方式。

### 2.1 CREATE 操作码(传统方式)

使用部署者的 **nonce**(交易计数器)生成地址:

$$
\text{address} = \text{keccak256}(\text{deployer\_address} \parallel \text{nonce})
$$

其中:
- `deployer_address` 是部署者的地址
- `nonce` 是部署者的交易计数器(每次交易后递增)

**示例**:

```javascript
// Alice 部署合约(nonce = 5)
地址1 = keccak256(Alice的地址, 5)

// Alice 再次部署同样的合约(nonce = 6)
地址2 = keccak256(Alice的地址, 6)

// 结果:两次部署产生不同的地址!
地址1 ≠ 地址2
```

**缺点**:
- ❌ 地址不可预测(nonce 会随交易变化)
- ❌ 要找到某个合约的部署 nonce,需要扫描历史交易
- ❌ 难以在其他合约中提前计算地址

### 2.2 CREATE2 操作码(确定性部署)

使用自定义的 **salt**(盐值)生成地址:

$$
\text{address} = \text{keccak256}(0xff \parallel \text{deployer} \parallel \text{salt} \parallel \text{bytecodeHash})
$$

其中:
- `0xff` 是固定前缀,用于区分 CREATE 和 CREATE2
- `deployer` 是部署者地址
- `salt` 是自定义的唯一标识符
- `bytecodeHash` 是合约字节码的哈希值

**Uniswap V3 的 salt 计算**:

```solidity
salt = keccak256(abi.encodePacked(token0, token1, tickSpacing))
```

**示例**:

```javascript
// 第一次部署 ETH/USDC 池子(tick spacing = 60)
salt = keccak256("ETH", "USDC", 60)
地址1 = keccak256(0xff, Factory地址, salt, 池子代码哈希)

// 一年后,再次用相同参数部署
salt = keccak256("ETH", "USDC", 60)  // 相同的 salt
地址2 = keccak256(0xff, Factory地址, salt, 池子代码哈希)

// 结果:两次部署产生相同的地址!
地址1 == 地址2
```

**优点**:
- ✅ 地址完全确定(只要 salt 相同,地址不变)
- ✅ 可以在部署前预先计算地址
- ✅ 便于跨合约引用和验证
- ✅ 无需查询注册表,任何人都能计算出池子地址

### 2.3 CREATE2 的安全特性

**防止地址冲突**:

CREATE2 的地址计算中包含了 `bytecodeHash`,这意味着:

```javascript
// 即使 salt 相同,不同的合约代码也会产生不同的地址
地址A = keccak256(0xff, deployer, salt, hash(ContractA的代码))
地址B = keccak256(0xff, deployer, salt, hash(ContractB的代码))

// 结果:地址A ≠ 地址B
```

这避免了恶意合约伪装成池子合约的风险。

## 三、Tick Spacing:价格间距的权衡

### 3.1 什么是 Tick Spacing?

回顾一下我们在 `swap` 函数中的循环逻辑:

```solidity
while (
    state.amountSpecifiedRemaining > 0 &&
    state.sqrtPriceX96 != sqrtPriceLimitX96
) {
    // 查找下一个有流动性的 tick
    (step.nextTick, ) = tickBitmap.nextInitializedTickWithinOneWord(...);

    // 计算交换步骤
    (state.sqrtPriceX96, step.amountIn, step.amountOut) =
        SwapMath.computeSwapStep(...);
}
```

这个循环需要**逐个遍历 tick**,直到找到有流动性的位置。如果目标 tick 很远,就需要遍历大量的 tick,**消耗大量 gas**!

**Tick Spacing 的作用**:设置 tick 之间的最小间隔,减少遍历次数。

**生活化类比**:

想象 tick 是高速公路上的服务区:

- **小间距(10)**:每 10 公里一个服务区 → 方便,但建设成本高
- **中间距(60)**:每 60 公里一个服务区 → 平衡
- **大间距(200)**:每 200 公里一个服务区 → 省钱,但不太方便

开车时,你会跳过没有服务区的地方,直接开到下一个服务区。tick spacing 就是让合约"跳过"没有流动性的 tick,直接到下一个有流动性的位置。

### 3.2 Tick Spacing 的权衡

| 属性 | 小间距(10) | 中间距(60) | 大间距(200) |
|------|-----------|-----------|------------|
| **Gas 效率** | 低(遍历多) | 中等 | 高(遍历少) |
| **价格精度** | 高 | 中等 | 低 |
| **适用场景** | 稳定币对 | 主流代币对 | 高波动率代币对 |
| **示例** | USDC/USDT | ETH/USDC | MEME币/ETH |

**权衡公式**:

$$
\text{Gas 效率} \uparrow \quad \Leftrightarrow \quad \text{价格精度} \downarrow
$$

### 3.3 Tick Spacing 的技术约束

**重要规则**:只有能被 tick spacing 整除的 tick 才能被标记为"已初始化"。

**示例**:当 tick spacing = 60 时:

```javascript
// ✅ 有效的 tick(可以作为流动性范围的边界)
-120, -60, 0, 60, 120, 180, 240...

// ❌ 无效的 tick(不能作为流动性范围的边界)
-59, -1, 10, 61, 100, 119...
```

**代码验证**:

```solidity
// 添加流动性时的检查
function mint(int24 tickLower, int24 tickUpper, uint128 amount) external {
    // 确保边界 tick 符合 spacing 要求
    require(tickLower % tickSpacing == 0, "Invalid tickLower");
    require(tickUpper % tickSpacing == 0, "Invalid tickUpper");

    // ...继续执行
}
```

**关键点**:

> ⚠️ **Tick spacing 只限制流动性范围的边界,不限制当前价格!**

当前价格可以是任意 tick,以保证最高精度:

```javascript
// 池子状态
tickSpacing = 60          // 流动性边界必须是 60 的倍数
currentTick = 85432       // 当前价格可以是任意 tick ✅

// 用户添加流动性
tickLower = 85380         // 85380 % 60 == 0 ✅
tickUpper = 85440         // 85440 % 60 == 0 ✅
```

### 3.4 UniswapV3 的 Tick Spacing 配置

Uniswap V3 支持三种 tick spacing(对应不同的费率档位):

| Tick Spacing | 费率 | 适用场景 | 示例代币对 |
|-------------|------|---------|-----------|
| **10** | 0.05% | 稳定币对 | USDC/USDT, DAI/USDC |
| **60** | 0.30% | 主流代币对 | ETH/USDC, WBTC/ETH |
| **200** | 1.00% | 高风险代币对 | SHIB/ETH, 新币/ETH |

从现在开始,我们在示例中使用:
- 常规池子:tick spacing = **60**
- 稳定币池:tick spacing = **10**

## 四、工厂合约实现

### 4.1 合约结构与状态变量

```solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.30;

import "./interfaces/IUniswapV3PoolDeployer.sol";
import "./UniswapV3Pool.sol";

/// @title Uniswap V3 池子工厂合约
/// @notice 负责创建和管理所有的交易池
contract UniswapV3Factory is IUniswapV3PoolDeployer {
    /// @notice 记录哪些 tick spacing 是被支持的
    /// @dev 使用 mapping 而非常量,便于未来扩展不同费率的 tick spacing
    mapping(uint24 => bool) public tickSpacings;

    /// @notice 临时存储池子初始化参数(仅在部署期间使用)
    /// @dev 使用"控制反转"模式传递参数给 Pool 构造函数
    PoolParameters public parameters;

    /// @notice 三维映射:token0 => token1 => tickSpacing => pool地址
    /// @dev 双向存储(token0→token1 和 token1→token0),方便查询
    mapping(address => mapping(address => mapping(uint24 => address)))
        public pools;

    /// @notice 池子创建事件
    event PoolCreated(
        address indexed token0,
        address indexed token1,
        uint24 indexed tickSpacing,
        address pool
    );

    // ========== 自定义错误(节省 gas) ==========
    error TokensMustBeDifferent();
    error UnsupportedTickSpacing();
    error TokenXCannotBeZero();
    error PoolAlreadyExists();

    constructor() {
        // 初始化支持的 tick spacing
        tickSpacings[10] = true;  // 稳定币对(0.05% 费率)
        tickSpacings[60] = true;  // 常规代币对(0.30% 费率)
    }

    // ...其他函数
}
```

**设计要点**:

1. **为什么用 mapping 存储 tickSpacings?**
   - 虽然现在只有两个值,看起来用常量更简单
   - 但未来可能增加新的费率档位,mapping 更灵活
   - 方便管理员动态启用/禁用某些 tick spacing

2. **为什么需要 parameters 临时变量?**
   - 这是"控制反转"模式的核心
   - 在部署期间临时存储参数,供 Pool 构造函数读取
   - 部署完成后立即删除,退还 gas

3. **为什么用三维 mapping?**
   - 第一维:token0 地址
   - 第二维:token1 地址
   - 第三维:tick spacing
   - 这样可以支持同一代币对的多个池子(不同 tick spacing)

### 4.2 createPool 函数 - 创建新池子

```solidity
/// @notice 创建一个新的交易池
/// @param tokenX 代币 X 地址
/// @param tokenY 代币 Y 地址
/// @param tickSpacing Tick 间距(决定价格精度)
/// @return pool 新创建的池子地址
function createPool(
    address tokenX,
    address tokenY,
    uint24 tickSpacing
) public returns (address pool) {
    // ========== 第一步:输入验证 ==========

    // 检查代币地址不能相同
    if (tokenX == tokenY) revert TokensMustBeDifferent();

    // 检查 tick spacing 是否被支持
    if (!tickSpacings[tickSpacing]) revert UnsupportedTickSpacing();

    // ========== 第二步:代币排序 ==========
    // 确保 token0 < token1(地址数值比较)
    // 这是为了保证同一代币对只有唯一的 salt
    (tokenX, tokenY) = tokenX < tokenY
        ? (tokenX, tokenY)
        : (tokenY, tokenX);

    // token0 不能是零地址
    if (tokenX == address(0)) revert TokenXCannotBeZero();

    // 检查池子是否已存在
    if (pools[tokenX][tokenY][tickSpacing] != address(0)) {
        revert PoolAlreadyExists();
    }

    // ========== 第三步:设置部署参数 ==========
    // 使用控制反转模式传递参数
    parameters = PoolParameters({
        factory: address(this),
        token0: tokenX,
        token1: tokenY,
        tickSpacing: tickSpacing
    });

    // ========== 第四步:使用 CREATE2 部署池子 ==========
    pool = address(
        new UniswapV3Pool{
            salt: keccak256(abi.encodePacked(tokenX, tokenY, tickSpacing))
        }()
    );

    // ========== 第五步:清理临时参数 ==========
    // 删除参数可以退还 gas
    delete parameters;

    // ========== 第六步:记录池子地址 ==========
    // 双向记录,方便查询
    pools[tokenX][tokenY][tickSpacing] = pool;
    pools[tokenY][tokenX][tickSpacing] = pool;

    // 发出事件
    emit PoolCreated(tokenX, tokenY, tickSpacing, pool);
}
```

### 4.3 代币排序的重要性

**为什么要排序代币地址?**

```solidity
(tokenX, tokenY) = tokenX < tokenY ? (tokenX, tokenY) : (tokenY, tokenX);
```

假设我们不排序,会发生什么?

```javascript
// 用户 Alice 创建 ETH/USDC 池子
factory.createPool(ETH, USDC, 60)
// salt = keccak256(ETH, USDC, 60)
// pool地址 = 0xAAAA...

// 用户 Bob 创建 USDC/ETH 池子(顺序相反)
factory.createPool(USDC, ETH, 60)
// salt = keccak256(USDC, ETH, 60)  // ⚠️ 不同的 salt!
// pool地址 = 0xBBBB...             // ⚠️ 不同的地址!

// 结果:同一个代币对出现了两个池子!
```

**排序后**:

```javascript
// 无论参数顺序如何,都会排序为 token0 < token1
createPool(ETH, USDC, 60)  → salt = keccak256(ETH, USDC, 60) → 0xAAAA
createPool(USDC, ETH, 60)  → salt = keccak256(ETH, USDC, 60) → 0xAAAA
                              ↑ 参数被重新排序

// 结果:第二次创建会失败(池子已存在)
```

**影响范围**:

这个排序规则会影响到:

1. **部署脚本**:需要确保 WETH 是 token0
2. **测试代码**:需要按地址大小排序代币
3. **价格计算**:token0/token1 的顺序决定了价格方向

```javascript
// ✅ 正确:WETH < USDC(假设地址更小)
价格 = 5000 USDC/ETH  // 1 ETH = 5000 USDC

// ❌ 错误:USDC < WETH(顺序反了)
价格 = 0.0002 ETH/USDC  // 1 USDC = 0.0002 ETH(这是倒数!)
```

### 4.4 控制反转(IoC)模式详解

这是一个非常巧妙的设计模式,让我们深入理解它。

**传统方式**(不推荐):

```solidity
// Pool 合约
constructor(
    address _factory,
    address _token0,
    address _token1,
    uint24 _tickSpacing
) {
    factory = _factory;
    token0 = _token0;
    token1 = _token1;
    tickSpacing = _tickSpacing;
}

// Factory 合约部署池子
new UniswapV3Pool{salt: ...}(
    address(this),  // 参数1
    tokenX,         // 参数2
    tokenY,         // 参数3
    tickSpacing     // 参数4
);
```

**控制反转方式**(Uniswap 使用):

```solidity
// Factory 合约
parameters = PoolParameters({...});  // 设置临时参数
new UniswapV3Pool();                 // 无参数部署
delete parameters;                   // 清理

// Pool 合约
constructor() {
    // 主动从部署者读取参数
    (factory, token0, token1, tickSpacing) =
        IUniswapV3PoolDeployer(msg.sender).parameters();
}
```

**执行时序图**:

```
时间轴
  │
  ├─ 1️⃣ 用户调用 factory.createPool(tokenX, tokenY, tickSpacing)
  │
  ├─ 2️⃣ Factory 设置临时参数
  │     parameters = PoolParameters({
  │         factory: address(this),
  │         token0: tokenX,
  │         token1: tokenY,
  │         tickSpacing: tickSpacing
  │     })
  │
  ├─ 3️⃣ Factory 使用 CREATE2 部署 Pool
  │     new UniswapV3Pool{salt: ...}()
  │     │
  │     ├─ 4️⃣ Pool 构造函数执行
  │     │     constructor() {
  │     │         // msg.sender 是 Factory 地址
  │     │         // 主动回调 Factory 读取参数
  │     │         (factory, token0, token1, tickSpacing) =
  │     │             IUniswapV3PoolDeployer(msg.sender).parameters();
  │     │     }
  │     │
  │     └─ 5️⃣ Pool 初始化完成,返回地址
  │
  ├─ 6️⃣ Factory 清空临时参数
  │     delete parameters;  // 退还 gas
  │
  └─ 7️⃣ 返回 Pool 地址给用户
```

**优势总结**:

| 方面 | 传统方式 | 控制反转 |
|------|---------|----------|
| **构造函数参数** | 4 个参数 | 0 个参数 |
| **部署 gas 消耗** | 较高 | 较低 |
| **代码可读性** | 参数传递明确 | 需要理解 IoC 模式 |
| **gas 退还** | 无 | 使用 delete 退还 |
| **灵活性** | 低 | 高(易于扩展参数) |

## 五、池子初始化分离

### 5.1 为什么要分离构造和初始化?

之前我们在构造函数中设置初始价格:

```solidity
// ❌ 旧方式:在构造函数中初始化价格
constructor(uint160 sqrtPriceX96) {
    slot0.sqrtPriceX96 = sqrtPriceX96;
    // ...
}
```

现在改为独立的 `initialize` 函数:

```solidity
// ✅ 新方式:分离部署和初始化
constructor() {
    // 只设置基本参数,不设置价格
}

function initialize(uint160 sqrtPriceX96) external {
    // 设置初始价格
}
```

**为什么要这样做?**

1. **灵活性** 🔄:部署和初始化可以由不同账户完成
2. **安全性** 🔐:初始化参数可以在部署后再确定
3. **标准化** 📏:所有池子遵循统一的部署流程
4. **gas 优化** ⛽:避免在部署时传递过多参数

### 5.2 initialize 函数实现

```solidity
// src/UniswapV3Pool.sol

/// @notice 池子初始化错误
error AlreadyInitialized();

/// @notice 初始化池子价格
/// @param sqrtPriceX96 初始价格的 Q64.96 格式平方根
/// @dev 该函数只能调用一次
function initialize(uint160 sqrtPriceX96) public {
    // 防止重复初始化
    if (slot0.sqrtPriceX96 != 0) revert AlreadyInitialized();

    // 根据价格计算对应的 tick
    int24 tick = TickMath.getTickAtSqrtRatio(sqrtPriceX96);

    // 设置初始状态
    slot0 = Slot0({
        sqrtPriceX96: sqrtPriceX96,
        tick: tick
    });
}
```

**防重入保护**:

```solidity
if (slot0.sqrtPriceX96 != 0) revert AlreadyInitialized();
```

这个检查确保了:

- ✅ gas 高效(只读取一个存储槽)

## 六、PoolAddress 库:离线计算池子地址

### 6.1 为什么需要这个库?

在很多场景下,我们需要在**不调用 Factory** 的情况下找到池子地址:

**场景1:Manager 合约中的交换**

```solidity
// ❌ 不推荐:每次都查询 Factory
address pool = factory.pools(token0, token1, tickSpacing);  // 外部调用,耗费 gas
IUniswapV3Pool(pool).swap(...);

// ✅ 推荐:直接计算地址
address pool = PoolAddress.computeAddress(factory, token0, token1, tickSpacing);  // 纯计算,不耗费 gas
IUniswapV3Pool(pool).swap(...);
```

**场景2:验证池子地址**

```solidity
// 防止用户传入恶意合约地址
function swap(address pool, ...) external {
    // 计算正确的池子地址
    address expectedPool = PoolAddress.computeAddress(...);

    // 验证传入的地址是否正确
    require(pool == expectedPool, "Invalid pool");

    // 安全执行交换
    IUniswapV3Pool(pool).swap(...);
}
```

**场景3:前端查询**

前端可以直接计算池子地址,无需调用合约:

```typescript
// 在前端直接计算,无需 RPC 调用
const poolAddress = computePoolAddress(factory, tokenA, tokenB, tickSpacing);

// 直接连接到池子合约
const pool = new ethers.Contract(poolAddress, PoolABI, provider);
```

### 6.2 computeAddress 函数实现

```solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.30;

import "../UniswapV3Pool.sol";

/// @title 池子地址计算库
/// @notice 提供离线计算池子地址的功能
library PoolAddress {
    /// @notice 计算池子的确定性地址
    /// @param factory Factory 合约地址
    /// @param token0 代币0地址(必须 < token1)
    /// @param token1 代币1地址
    /// @param tickSpacing Tick 间距
    /// @return pool 计算出的池子地址
    function computeAddress(
        address factory,
        address token0,
        address token1,
        uint24 tickSpacing
    ) internal pure returns (address pool) {
        // 确保代币已排序
        require(token0 < token1, "Tokens not sorted");

        // 按照 CREATE2 规则计算地址
        pool = address(
            uint160(                          // 6. 转换为地址类型(取低 160 位)
                uint256(                      // 5. 转换为 uint256
                    keccak256(                // 4. 对整体进行哈希
                        abi.encodePacked(     // 3. 打包所有参数
                            // ========== CREATE2 的四个组成部分 ==========

                            // 组成部分1:CREATE2 标识前缀
                            hex"ff",

                            // 组成部分2:部署者(Factory)地址
                            factory,

                            // 组成部分3:Salt(唯一标识符)
                            keccak256(        // 2. 对 salt 参数进行哈希
                                abi.encodePacked(token0, token1, tickSpacing)
                            ),

                            // 组成部分4:池子合约的代码哈希
                            keccak256(type(UniswapV3Pool).creationCode)  // 1. 获取合约创建代码并哈希
                        )
                    )
                )
            )
        );
    }
}
```

### 6.3 CREATE2 地址计算详解

让我们逐步分析这个计算过程:

#### 步骤1:获取合约代码哈希

```solidity
keccak256(type(UniswapV3Pool).creationCode)
```

- `type(UniswapV3Pool).creationCode` 获取 Pool 合约的**创建字节码**
- 创建字节码包含:合约代码 + 构造函数逻辑
- 哈希后得到一个固定的 32 字节值

**为什么需要代码哈希?**

防止地址冲突:即使 salt 相同,不同的合约代码也会产生不同的地址。

#### 步骤2:计算 Salt

```solidity
keccak256(abi.encodePacked(token0, token1, tickSpacing))
```

- 将三个参数紧密打包(无填充)
- 对打包后的数据进行哈希
- 得到一个唯一的 32 字节 salt

**示例**:

```javascript
token0 = 0xC02aaA39b223FE8D0A0e5C4F27eAD9083C756Cc2  // WETH
token1 = 0xA0b86991c6218b36c1d19D4a2e9Eb0cE3606eB48  // USDC
tickSpacing = 60

// 打包
packed = 0xC02aaA39...Cc20xA0b8699...eB4800003c
         └─ WETH ──┘└─ USDC ──┘└tick┘

// 哈希
salt = keccak256(packed)
     = 0x1234567890abcdef...
```

#### 步骤3:组合所有参数

```solidity
abi.encodePacked(
    hex"ff",              // 1 字节
    factory,              // 20 字节
    salt,                 // 32 字节
    codeHash              // 32 字节
)
// 总共 85 字节
```

#### 步骤4-6:哈希并转换为地址

```solidity
hash = keccak256(packed)           // 得到 32 字节哈希
uint = uint256(hash)               // 转换为 uint256
addr = address(uint160(uint))      // 取低 160 位作为地址
```

**为什么取低 160 位?**

以太坊地址是 20 字节(160 位),而 keccak256 输出是 32 字节。我们取哈希值的后 20 字节作为地址。

### 6.4 CREATE2 地址计算的数学表示

完整的 CREATE2 地址计算公式:

$$
\text{address} = \text{address}(\text{uint160}(\text{uint256}(\text{keccak256}(\text{data}))))
$$

其中:

$$
\text{data} = 0xff \parallel \text{factory} \parallel \text{keccak256}(\text{token0} \parallel \text{token1} \parallel \text{tickSpacing}) \parallel \text{keccak256}(\text{creationCode})
$$

### 6.5 使用示例

```solidity
// 在 Manager 合约中使用
function swap(
    address tokenIn,
    address tokenOut,
    uint24 tickSpacing,
    uint256 amountIn

    // 1. 排序代币

        ? (tokenIn, tokenOut)

```

## 七、简化 Manager 和 Quoter 接口

### 7.1 不再需要池子地址参数

**之前的接口**(繁琐):

```solidity
function swap(
```

用户需要:
1. 查询 Factory 找到池子地址
2. 判断代币顺序,确定 zeroForOne
3. 才能调用 swap

**优化后的接口**(简洁):

```solidity
function swap(
    address tokenIn,      // ✅ 只需输入代币地址
    address tokenOut,     // ✅ 只需输出代币地址
    uint24 tickSpacing,   // ✅ Tick 间距
    uint256 amountIn      // ✅ 输入数量
) external;
```

用户只需提供代币地址,合约自动:
1. 排序代币
2. 计算池子地址
3. 判断交换方向

### 7.2 自动判断交换方向

**原理**:

```solidity
// 根据代币排序自动判断 zeroForOne
function getSwapDirection(
    address tokenIn,
    address tokenOut
) internal pure returns (bool zeroForOne) {
    // token0 → token1: zeroForOne = true
    // token1 → token0: zeroForOne = false
    zeroForOne = tokenIn < tokenOut;
}
```

**为什么这样判断是正确的?**

池子中的代币是排序的:
- `token0` 永远小于 `token1`(按地址数值比较)

因此:
- 如果 `tokenIn < tokenOut`,则 `tokenIn` 是 `token0`,方向是 `true`
- 如果 `tokenIn > tokenOut`,则 `tokenIn` 是 `token1`,方向是 `false`

**示例**:

```javascript
// 假设地址排序:WETH(0x00AA...) < USDC(0x00BB...)

// 场景1:用 ETH 买 USDC
tokenIn  = WETH   // 0x00AA...
tokenOut = USDC   // 0x00BB...
zeroForOne = WETH < USDC = true  ✅ 正确!

// 场景2:用 USDC 买 ETH
tokenIn  = USDC   // 0x00BB...
tokenOut = WETH   // 0x00AA...
zeroForOne = USDC < WETH = false  ✅ 正确!
```

### 7.3 完整的 Manager.swap 实现

```solidity
// src/UniswapV3Manager.sol

/// @notice 执行代币交换
/// @param tokenIn 输入代币地址
/// @param tokenOut 输出代币地址
/// @param tickSpacing Tick 间距
/// @param amountIn 输入数量
/// @param sqrtPriceLimitX96 价格滑点保护
/// @return amountOut 实际获得的输出代币数量
function swap(
    address tokenIn,
    address tokenOut,
    uint24 tickSpacing,
    uint256 amountIn,
    uint160 sqrtPriceLimitX96
) external returns (uint256 amountOut) {
    // ========== 1. 排序代币 ==========
    (address token0, address token1) = tokenIn < tokenOut
        ? (tokenIn, tokenOut)
        : (tokenOut, tokenIn);

    // ========== 2. 计算池子地址 ==========
    address pool = PoolAddress.computeAddress(
        factory,
        token0,
        token1,
        tickSpacing
    );

    // ========== 3. 确定交换方向 ==========
    bool zeroForOne = tokenIn < tokenOut;

    // ========== 4. 执行交换 ==========
    (int256 amount0, int256 amount1) = IUniswapV3Pool(pool).swap(
        msg.sender,              // 接收代币的地址
        zeroForOne,              // 交换方向
        int256(amountIn),        // 输入数量(转为有符号数)
        sqrtPriceLimitX96,       // 滑点保护
        abi.encode(msg.sender)   // 回调数据
    );

    // ========== 5. 返回输出数量 ==========
    // 根据方向选择对应的 amount
    amountOut = uint256(-(zeroForOne ? amount1 : amount0));
}
```

**代码解析**:

#### 为什么输出是负数?

在 Pool 合约中:
- 正数表示**流入**池子的代币
- 负数表示**流出**池子的代币

```javascript
// zeroForOne = true(token0 → token1)
amount0 = +1000  // 用户支付 1000 token0(流入)
amount1 = -950   // 用户获得 950 token1(流出)

// 我们需要的是"流出"的数量
amountOut = uint256(-amount1) = 950
```

#### 三元运算符的选择逻辑

```solidity
amountOut = uint256(-(zeroForOne ? amount1 : amount0));
```

- 如果 `zeroForOne = true`:用 token0 买 token1,输出是 `amount1`
- 如果 `zeroForOne = false`:用 token1 买 token0,输出是 `amount0`

## 八、核心知识点回顾

### 8.1 工厂合约的三大功能

| 功能 | 说明 | 收益 |
|------|------|------|
| **集中注册表** 📋 | 记录所有池子的映射关系 | 快速查找池子地址 |
| **标准化部署** 🏭 | 使用工厂模式创建池子 | 降低部署复杂度 |
| **确定性地址** 🔮 | 使用 CREATE2 生成地址 | 无需查询即可计算地址 |

### 8.2 Tick Spacing 的权衡

```
Gas 效率 ↑ ←→ 价格精度 ↓

大间距(200) → 高波动率代币对 → 节省 gas
中间距(60)  → 常规代币对       → 平衡
小间距(10)  → 稳定币对         → 高精度
```

### 8.3 CREATE2 vs CREATE

| 特性 | CREATE | CREATE2 |
|------|--------|---------|
| **地址计算** | `hash(部署者, nonce)` | `hash(0xff, 部署者, salt, 代码哈希)` |
| **确定性** | ❌ 依赖 nonce | ✅ 完全确定 |
| **可预测性** | ❌ 需要查询历史 | ✅ 可提前计算 |
| **Uniswap 使用** | ❌ | ✅ |

### 8.4 控制反转模式的优势

**传统构造函数**:
```solidity
constructor(address _factory, address _token0, address _token1, uint24 _tickSpacing) {
    // ❌ 参数多,gas 消耗高
}
```

**控制反转**:
```solidity
constructor() {
    // ✅ 从部署者读取参数,更优雅
    (...) = IDeployer(msg.sender).parameters();
}
```

**优势**:
- ✅ 减少构造函数参数
- ✅ Pool 合约代码更简洁
- ✅ 使用 `delete` 退还 gas
- ✅ 易于扩展参数

### 8.5 接口简化的收益

**之前**:
```solidity
swap(poolAddress, zeroForOne, amount)  // 用户需要提供 3 个参数
```

**现在**:
```solidity
swap(tokenIn, tokenOut, tickSpacing, amount)  // 合约自动计算池子地址和方向
```
