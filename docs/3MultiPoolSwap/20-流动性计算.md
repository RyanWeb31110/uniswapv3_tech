## 一、流动性计算的数学基础

### 1.1 回顾流动性公式

在第五章《流动性计算》中，我们详细推导了流动性的数学公式。让我们快速回顾一下核心概念：

**流动性 L 的定义**：

$$
L = \sqrt{x \cdot y}
$$

其中 `x` 和 `y` 是两种代币的储备量。

但在 UniswapV3 中，由于引入了集中流动性和价格区间，我们需要更精确的计算方式。

### 1.2 两种流动性计算公式

根据不同的已知条件，我们有两种计算流动性的公式：

**（1）基于代币 X（如 ETH）的流动性计算**

当我们知道代币 X 的数量和价格区间时：

$$
\Delta x = \Delta \frac{1}{\sqrt{P}} \cdot L
$$

反推得到：

$$
L = \frac{\Delta x}{\Delta \frac{1}{\sqrt{P}}}
$$

展开后：

$$
L = \frac{\Delta x \cdot \sqrt{P_u} \cdot \sqrt{P_l}}{\sqrt{P_u} - \sqrt{P_l}}
$$

其中：
- `Δx` 是代币 X 的数量
- `P_l` 是价格区间下限
- `P_u` 是价格区间上限
- `√P` 表示价格的平方根

**（2）基于代币 Y（如 USDC）的流动性计算**

当我们知道代币 Y 的数量和价格区间时：

$$
\Delta y = \Delta \sqrt{P} \cdot L
$$

反推得到：

$$
L = \frac{\Delta y}{\Delta \sqrt{P}}
$$

展开后：

$$
L = \frac{\Delta y}{\sqrt{P_u} - \sqrt{P_l}}
$$

### 1.3 为什么需要两个公式？

你可能会疑惑：流动性 L 只有一个，为什么有两种计算方法？

答案是：**这两个公式都是正确的**，但它们适用于不同的场景。关键在于当前价格与价格区间的位置关系：

- 🔼 **当前价格在区间上方**：只需要代币 Y，使用基于 Y 的公式
- 🔽 **当前价格在区间下方**：只需要代币 X，使用基于 X 的公式
- 📍 **当前价格在区间内部**：需要两种代币，计算两个 L 并选择较小值

让我们用一个形象的比喻来理解：

> 🏊 **流动性就像水库的容量**
>
> - 如果当前水位（价格）低于水库底部（区间下限），你只需要准备沙石（代币 X）来垫高
> - 如果当前水位高于水库顶部（区间上限），你只需要准备水（代币 Y）来蓄水
> - 如果当前水位在水库中间，你需要准备沙石和水，但要确保它们匹配，所以选择较小的那个

## 二、准备工作：安装 PRBMath 库

### 2.1 为什么需要 PRBMath？

在 Solidity 中进行精确的数学运算非常具有挑战性，主要面临以下问题：

1. **溢出风险**：两个大数相乘很容易超过 `uint256` 的最大值
2. **精度损失**：整数除法会丢失小数部分
3. **运算顺序**：先乘后除和先除后乘的结果可能不同

PRBMath 是一个专业的 Solidity 数学库，提供了：

- ✅ **高精度运算**：在中间步骤使用 512 位精度
- ✅ **溢出保护**：自动处理大数运算
- ✅ **mulDiv 函数**：计算 `(a * b) / c` 而不会溢出

这就是为什么 Uniswap V3 的所有数学运算都依赖这个库。

## 三、Solidity 实现：代币 X 的流动性计算

### 3.1 函数设计

让我们先实现基于代币 X（ETH）数量的流动性计算：

```solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.14;

import "./FixedPoint96.sol";
import "prb-math/Common.sol" as PRBMath;

/// @title LiquidityAmounts
/// @notice 流动性数量计算库，用于根据代币数量和价格区间计算流动性
library LiquidityAmounts {

    /// @notice 根据代币0的数量计算流动性
    /// @dev 当价格区间在当前价格下方时使用此函数
    /// @param sqrtPriceAX96 价格区间下限的平方根价格（Q64.96格式）
    /// @param sqrtPriceBX96 价格区间上限的平方根价格（Q64.96格式）
    /// @param amount0 代币0的数量
    /// @return liquidity 计算得到的流动性
    function getLiquidityForAmount0(
        uint160 sqrtPriceAX96,
        uint160 sqrtPriceBX96,
        uint256 amount0
    ) internal pure returns (uint128 liquidity) {
        // 确保 sqrtPriceA <= sqrtPriceB
        if (sqrtPriceAX96 > sqrtPriceBX96) {
            (sqrtPriceAX96, sqrtPriceBX96) = (sqrtPriceBX96, sqrtPriceAX96);
        }

        // 计算中间值：sqrt(P_lower) * sqrt(P_upper) / Q96
        // 这对应公式中的分子部分
        uint256 intermediate = PRBMath.mulDiv(
            sqrtPriceAX96,
            sqrtPriceBX96,
            FixedPoint96.Q96
        );

        // 计算流动性：amount0 * intermediate / (sqrtPriceB - sqrtPriceA)
        liquidity = uint128(
            PRBMath.mulDiv(
                amount0,
                intermediate,
                sqrtPriceBX96 - sqrtPriceAX96
            )
        );
    }
}
```

### 3.2 代码详解

**（1）参数验证和排序**

```solidity
if (sqrtPriceAX96 > sqrtPriceBX96) {
    (sqrtPriceAX96, sqrtPriceBX96) = (sqrtPriceBX96, sqrtPriceAX96);
}
```

确保 `sqrtPriceA` 始终小于 `sqrtPriceB`，这样可以避免后续计算出现负数。

**（2）计算分子的中间值**

```solidity
uint256 intermediate = PRBMath.mulDiv(
    sqrtPriceAX96,
    sqrtPriceBX96,
    FixedPoint96.Q96
);
```

这一步计算：

$$
\frac{\sqrt{P_l} \cdot \sqrt{P_u}}{Q96}
$$

**为什么要除以 Q96？**

因为两个 Q64.96 格式的数相乘后，小数点位数会翻倍，变成 Q64.192。我们需要除以 2<sup>96</sup> 来恢复到 Q64.96 格式。

**（3）计算最终流动性**

```solidity
liquidity = uint128(
    PRBMath.mulDiv(
        amount0,
        intermediate,
        sqrtPriceBX96 - sqrtPriceAX96
    )
);
```

这对应公式：

$$
L = \frac{\Delta x \cdot \sqrt{P_u} \cdot \sqrt{P_l}}{\sqrt{P_u} - \sqrt{P_l}}
$$

### 3.3 PRBMath.mulDiv 的优势

**为什么不直接用 `a * b / c`？**

直接计算可能导致：
```solidity
// ❌ 错误：可能溢出
uint256 result = (sqrtPriceA * sqrtPriceB) / Q96;

// ✅ 正确：使用 PRBMath
uint256 result = PRBMath.mulDiv(sqrtPriceA, sqrtPriceB, Q96);
```

PRBMath.mulDiv 的三大优势：
- ✅ 中间步骤使用 512 位精度，避免溢出
- ✅ 正确的舍入策略，保证精度
- ✅ Gas 优化，比手动实现更高效

## 四、Solidity 实现：代币 Y 的流动性计算

### 4.1 函数实现

基于代币 Y（USDC）的流动性计算相对简单：

```solidity
/// @notice 根据代币1的数量计算流动性
/// @dev 当价格区间在当前价格上方时使用此函数
/// @param sqrtPriceAX96 价格区间下限的平方根价格（Q64.96格式）
/// @param sqrtPriceBX96 价格区间上限的平方根价格（Q64.96格式）
/// @param amount1 代币1的数量
/// @return liquidity 计算得到的流动性
function getLiquidityForAmount1(
    uint160 sqrtPriceAX96,
    uint160 sqrtPriceBX96,
    uint256 amount1
) internal pure returns (uint128 liquidity) {
    // 确保 sqrtPriceA <= sqrtPriceB
    if (sqrtPriceAX96 > sqrtPriceBX96) {
        (sqrtPriceAX96, sqrtPriceBX96) = (sqrtPriceBX96, sqrtPriceAX96);
    }

    // 计算流动性：amount1 * Q96 / (sqrtPriceB - sqrtPriceA)
    liquidity = uint128(
        PRBMath.mulDiv(
            amount1,
            FixedPoint96.Q96,
            sqrtPriceBX96 - sqrtPriceAX96
        )
    );
}
```

### 4.2 代码解析

这个函数直接实现公式：

$$
L = \frac{\Delta y \cdot Q96}{\sqrt{P_u} - \sqrt{P_l}}
$$

**为什么要乘以 Q96？**

因为 `sqrtPriceAX96` 和 `sqrtPriceBX96` 都是 Q64.96 格式，它们的差值也是 Q64.96 格式。

为了保持精度，我们需要将 `amount1`（普通整数）转换为 Q64.96 格式，所以要乘以 2<sup>96</sup>。

### 4.3 与代币 X 计算的对比

让我们对比两个函数的复杂度：

| 计算类型 | 中间步骤 | 复杂度 |
|---------|---------|--------|
| 代币 X | 需要计算 `√P_l · √P_u` | 较高 |
| 代币 Y | 只需要计算价格差 | 较低 |

代币 Y 的计算更简单，因为公式本身就更直接。这也从侧面反映了 UniswapV3 数学设计的精妙之处。

## 五、寻找"公平流动性"

### 5.1 什么是公平流动性？

当价格区间包含当前价格时，我们需要提供两种代币。但问题来了：

> 用户提供的代币数量可能不匹配当前价格比例。

举个例子：

```
当前价格: 1 ETH = 5000 USDC
用户想提供: 10 ETH + 100,000 USDC

按当前价格计算:
- 基于 10 ETH 计算出的流动性: L1 = 1000
- 基于 100,000 USDC 计算出的流动性: L2 = 1500

应该选择哪个 L？
```

答案是：**选择较小的 L**。

### 5.2 为什么选择较小的 L？

选择较小的 L 是为了确保：

1. **不超支**：用户提供的两种代币都足够
2. **公平性**：不会要求用户提供超出他们预期的代币
3. **安全性**：避免计算错误导致的资金损失

用我们的例子说明：

```
选择 L = 1000（较小值）时：
- 需要 ETH: 10 枚（用户有）✅
- 需要 USDC: 50,000（用户有 100,000）✅
- 多余的 50,000 USDC 会退还给用户

选择 L = 1500（较大值）时：
- 需要 ETH: 15 枚（用户只有 10）❌
- 需要 USDC: 100,000（用户有）✅
- 用户 ETH 不足，交易会失败
```

### 5.3 完整实现

现在让我们实现完整的流动性计算逻辑：

```solidity
/// @notice 根据当前价格和代币数量计算流动性
/// @dev 根据当前价格的位置选择不同的计算方法
/// @param sqrtPriceX96 当前的平方根价格（Q64.96格式）
/// @param sqrtPriceAX96 价格区间下限的平方根价格（Q64.96格式）
/// @param sqrtPriceBX96 价格区间上限的平方根价格（Q64.96格式）
/// @param amount0 用户提供的代币0数量
/// @param amount1 用户提供的代币1数量
/// @return liquidity 计算得到的流动性
function getLiquidityForAmounts(
    uint160 sqrtPriceX96,
    uint160 sqrtPriceAX96,
    uint160 sqrtPriceBX96,
    uint256 amount0,
    uint256 amount1
) internal pure returns (uint128 liquidity) {
    // 确保价格区间有序
    if (sqrtPriceAX96 > sqrtPriceBX96) {
        (sqrtPriceAX96, sqrtPriceBX96) = (sqrtPriceBX96, sqrtPriceAX96);
    }

    // 情况1: 当前价格 < 价格区间下限
    // 只需要代币0（X），因为价格在区间下方
    if (sqrtPriceX96 <= sqrtPriceAX96) {
        liquidity = getLiquidityForAmount0(
            sqrtPriceAX96,
            sqrtPriceBX96,
            amount0
        );
    }
    // 情况2: 价格区间下限 <= 当前价格 <= 价格区间上限
    // 需要两种代币，选择较小的流动性
    else if (sqrtPriceX96 <= sqrtPriceBX96) {
        // 基于代币0计算流动性
        uint128 liquidity0 = getLiquidityForAmount0(
            sqrtPriceX96,      // 使用当前价格作为下限
            sqrtPriceBX96,     // 使用区间上限
            amount0
        );

        // 基于代币1计算流动性
        uint128 liquidity1 = getLiquidityForAmount1(
            sqrtPriceAX96,     // 使用区间下限
            sqrtPriceX96,      // 使用当前价格作为上限
            amount1
        );

        // 选择较小的流动性，确保两种代币都足够
        liquidity = liquidity0 < liquidity1 ? liquidity0 : liquidity1;
    }
    // 情况3: 当前价格 > 价格区间上限
    // 只需要代币1（Y），因为价格在区间上方
    else {
        liquidity = getLiquidityForAmount1(
            sqrtPriceAX96,
            sqrtPriceBX96,
            amount1
        );
    }
}
```

### 5.4 三种情况详解

让我们用图示理解这三种情况：

**情况 1：价格在区间下方**

```
当前价格 ↓
           |
    区间: [====下限========上限====]

需要：只需要代币0（ETH）
原因：价格需要上涨才能进入区间，需要买入代币0
```

**情况 2：价格在区间内部**

```
           当前价格 ↓
                    |
    区间: [====下限===|===上限====]

需要：两种代币都需要
原因：价格可能上涨或下跌，需要两种代币来应对
```

**情况 3：价格在区间上方**

```
                            当前价格 ↓
                                     |
    区间: [====下限========上限====]

需要：只需要代币1（USDC）
原因：价格需要下跌才能进入区间，需要买入代币1
```

## 六、在 Manager 合约中使用

### 6.1 集成到 mint 函数

现在我们可以在 Manager 合约的 `mint` 函数中使用这些计算函数：

```solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.14;

import "./lib/LiquidityAmounts.sol";
import "./UniswapV3Pool.sol";

contract UniswapV3Manager {

    /// @notice 添加流动性
    /// @param params 流动性参数
    /// @return amount0 实际投入的代币0数量
    /// @return amount1 实际投入的代币1数量
    function mint(MintParams calldata params)
        external
        returns (uint256 amount0, uint256 amount1)
    {
        IUniswapV3Pool pool = IUniswapV3Pool(params.poolAddress);

        // 获取池子的当前状态
        (uint160 sqrtPriceX96, int24 tick) = pool.slot0();

        // 计算价格区间的平方根价格
        uint160 sqrtPriceLowerX96 = TickMath.getSqrtRatioAtTick(params.lowerTick);
        uint160 sqrtPriceUpperX96 = TickMath.getSqrtRatioAtTick(params.upperTick);

        // 🎯 关键步骤：根据用户提供的代币数量和当前价格计算流动性
        uint128 liquidity = LiquidityAmounts.getLiquidityForAmounts(
            sqrtPriceX96,
            sqrtPriceLowerX96,
            sqrtPriceUpperX96,
            params.amount0Desired,  // 用户期望提供的代币0数量
            params.amount1Desired   // 用户期望提供的代币1数量
        );

        // 调用池子合约添加流动性
        (amount0, amount1) = pool.mint(
            params.recipient,
            params.lowerTick,
            params.upperTick,
            liquidity
        );

        // 验证实际使用的代币数量不超过用户的最大容忍值
        require(
            amount0 <= params.amount0Max && amount1 <= params.amount1Max,
            "Price slippage check"
        );

        // 从用户账户转移代币到池子
        // ... 转账逻辑
    }
}
```

### 6.2 完整的参数结构

```solidity
/// @notice 添加流动性的参数
struct MintParams {
    address poolAddress;       // 池子地址
    address recipient;         // 流动性接收者
    int24 lowerTick;          // 价格区间下限（tick）
    int24 upperTick;          // 价格区间上限（tick）
    uint256 amount0Desired;   // 期望提供的代币0数量
    uint256 amount1Desired;   // 期望提供的代币1数量
    uint256 amount0Max;       // 代币0的最大容忍数量（滑点保护）
    uint256 amount1Max;       // 代币1的最大容忍数量（滑点保护）
}
```

## 七、实战测试

### 7.1 测试场景设计

让我们编写测试来验证流动性计算的正确性：

```solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.14;

import "forge-std/Test.sol";
import "../src/lib/LiquidityAmounts.sol";
import "../src/lib/TickMath.sol";

contract LiquidityAmountsTest is Test {

    /// @notice 测试：当前价格在区间下方
    function test_GetLiquidity_PriceBelowRange() public {
        // 设置价格区间：4545 - 5500 USDC/ETH
        int24 lowerTick = 84222;  // 约 4545 USDC/ETH
        int24 upperTick = 86129;  // 约 5500 USDC/ETH

        uint160 sqrtPriceLower = TickMath.getSqrtRatioAtTick(lowerTick);
        uint160 sqrtPriceUpper = TickMath.getSqrtRatioAtTick(upperTick);

        // 当前价格：4000 USDC/ETH（低于区间下限）
        int24 currentTick = 83000;
        uint160 sqrtPriceCurrent = TickMath.getSqrtRatioAtTick(currentTick);

        // 用户提供：10 ETH + 100,000 USDC
        uint256 amount0 = 10 ether;
        uint256 amount1 = 100_000 * 1e6;  // USDC 有 6 位小数

        // 计算流动性
        uint128 liquidity = LiquidityAmounts.getLiquidityForAmounts(
            sqrtPriceCurrent,
            sqrtPriceLower,
            sqrtPriceUpper,
            amount0,
            amount1
        );

        // 由于价格在区间下方，流动性应该只基于 amount0 计算
        uint128 expectedLiquidity = LiquidityAmounts.getLiquidityForAmount0(
            sqrtPriceLower,
            sqrtPriceUpper,
            amount0
        );

        assertEq(liquidity, expectedLiquidity, "Liquidity should be based on amount0 only");
    }

    /// @notice 测试：当前价格在区间内部
    function test_GetLiquidity_PriceInRange() public {

        int24 lowerTick = 84222;
        int24 upperTick = 86129;

        uint160 sqrtPriceLower = TickMath.getSqrtRatioAtTick(lowerTick);
        uint160 sqrtPriceUpper = TickMath.getSqrtRatioAtTick(upperTick);

        // 当前价格：5000 USDC/ETH（在区间内部）
        int24 currentTick = 85176;
        uint160 sqrtPriceCurrent = TickMath.getSqrtRatioAtTick(currentTick);

        // 用户提供：1 ETH + 5000 USDC
        uint256 amount0 = 1 ether;
        uint256 amount1 = 5000 * 1e6;

        // 计算流动性
        uint128 liquidity = LiquidityAmounts.getLiquidityForAmounts(
            sqrtPriceCurrent,
            sqrtPriceLower,
            sqrtPriceUpper,
            amount0,
            amount1
        );

        // 分别计算基于两种代币的流动性
        uint128 liquidity0 = LiquidityAmounts.getLiquidityForAmount0(

        assertTrue(liquidity > 0, "Liquidity should be positive");
    }
```

## 八、与 Python 实现对比

### 8.1 Python 原型代码

让我们回顾在项目初期使用的 Python 计算代码：

```python
# unimath.py

# Q96 常量
q96 = 2**96

def liquidity0(amount, pa, pb):
    """基于代币0（X）计算流动性"""
    if pa > pb:
        pa, pb = pb, pa
    return (amount * (pa * pb) / q96) / (pb - pa)

def liquidity1(amount, pa, pb):
    """基于代币1（Y）计算流动性"""
    if pa > pb:
        pa, pb = pb, pa
    return amount * q96 / (pb - pa)

def liquidity_for_amounts(sqrtPrice, sqrtPriceA, sqrtPriceB, amount0, amount1):
    """根据当前价格和代币数量计算流动性"""
    if sqrtPriceA > sqrtPriceB:
        sqrtPriceA, sqrtPriceB = sqrtPriceB, sqrtPriceA

    # 价格在区间下方
    if sqrtPrice <= sqrtPriceA:
        return liquidity0(amount0, sqrtPriceA, sqrtPriceB)

    # 价格在区间内部
    elif sqrtPrice <= sqrtPriceB:
        liq0 = liquidity0(amount0, sqrtPrice, sqrtPriceB)
        liq1 = liquidity1(amount1, sqrtPriceA, sqrtPrice)
        return min(liq0, liq1)

    # 价格在区间上方
    else:
        return liquidity1(amount1, sqrtPriceA, sqrtPriceB)
```

### 8.2 Solidity vs Python 对比

| 特性 | Python 实现 | Solidity 实现 |
|------|------------|---------------|
| **类型安全** | 动态类型，容易出错 | 强类型，编译时检查 |
| **精度处理** | 浮点数，可能有精度损失 | 使用 PRBMath，保证精度 |
| **溢出保护** | 无自动保护 | 使用安全的数学库 |
| **Gas 优化** | 不适用 | 需要考虑 Gas 消耗 |
| **可读性** | 更直观 | 需要理解 Q64.96 格式 |

### 8.3 为什么先用 Python？

在项目早期，我们先用 Python 实现计算逻辑有以下好处：

1. ✅ **快速原型**：Python 语法简洁，可以快速验证数学公式
2. ✅ **易于调试**：可以打印中间值，方便发现问题
3. ✅ **测试数据生成**：生成测试用例，对比 Solidity 实现
4. ✅ **理解数学**：专注于数学逻辑，不被 Solidity 细节干扰

这是一种非常好的开发策略：**先理解数学，再优化实现**。

## 九、核心知识点回顾

### 9.1 流动性计算公式

**基于代币 X（ETH）**：

$$
L = \frac{\Delta x \cdot \sqrt{P_u} \cdot \sqrt{P_l}}{\sqrt{P_u} - \sqrt{P_l}}
$$

**基于代币 Y（USDC）**：

$$
L = \frac{\Delta y}{\sqrt{P_u} - \sqrt{P_l}}
$$

### 9.2 三种计算场景

| 场景 | 当前价格位置 | 使用公式 | 需要代币 |
|------|------------|---------|---------|
| 1 | 价格 < 区间下限 | 基于代币 X | 仅代币 X |
| 2 | 区间下限 ≤ 价格 ≤ 区间上限 | 两个公式都用 | 两种代币 |
| 3 | 价格 > 区间上限 | 基于代币 Y | 仅代币 Y |

### 9.3 "公平流动性"原则

- 当价格在区间内部时，计算两个流动性值
- 选择**较小**的流动性值
- 确保用户提供的两种代币都足够
- 多余的代币会退还给用户

### 9.4 实现要点

1. ✅ 使用 PRBMath 库处理乘除法，避免溢出
2. ✅ 正确处理 Q64.96 定点数格式
3. ✅ 确保价格区间有序（下限 < 上限）
4. ✅ 在不同价格位置选择正确的计算方法
5. ✅ 编写完整的测试覆盖所有场景

- ✅ 检查 Gas 消耗是否合理

### 10.3 常见错误

⚠️ **错误 1：忘记检查价格区间顺序**

```solidity
// ❌ 错误：没有检查顺序
liquidity = amount / (sqrtPriceB - sqrtPriceA);  // 如果 A > B，会溢出

// ✅ 正确：先检查顺序
if (sqrtPriceA > sqrtPriceB) {
    (sqrtPriceA, sqrtPriceB) = (sqrtPriceB, sqrtPriceA);
}
```

⚠️ **错误 2：直接相乘导致溢出**

```solidity
// ❌ 错误：可能溢出
uint256 result = amount0 * sqrtPriceA * sqrtPriceB / (sqrtPriceB - sqrtPriceA);

// ✅ 正确：使用 PRBMath
uint256 result = PRBMath.mulDiv(amount0, sqrtPriceA * sqrtPriceB / Q96, sqrtPriceB - sqrtPriceA);
```

⚠️ **错误 3：选择较大的流动性**

```solidity
// ❌ 错误：选择较大值会导致代币不足
liquidity = liquidity0 > liquidity1 ? liquidity0 : liquidity1;

// ✅ 正确：选择较小值确保代币足够
liquidity = liquidity0 < liquidity1 ? liquidity0 : liquidity1;
```
